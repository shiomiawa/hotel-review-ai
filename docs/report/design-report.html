設計書レポート　口コミAI分析＆返信支援アプリ

作成者：shiomiawa 公開URL：https://hotel-review-ai.vercel.app GitHub：https://github.com/shiomiawa/hotel-review-ai
ホテル・旅館のネットの口コミ（OTA・Google）と、現場で受けたお客様の声（アンケート・フロント・電話/メール・旅行会社/団体）をひとつにまとめ、同じ4つの視点で分析して「優先して改善すべき点」と「強み」を示すWebアプリ。 返信文の下書き作成は、分析と改善に時間を回すための補助機能として位置づける。

1. 背景と解決したい課題

  • 現場スタッフは口コミを見ても「返信文をどう書くか」に意識を取られ、口コミを業務改善に結び付けられていない。特に一言の好評口コミへの返信に迷い、時間がかかっている。
  • ネットの口コミと、現場で直接受けた声が別々に管理され、同じ不満が両方に出ていても気づきにくい。
  • コンセプト：返信に悩む時間を、改善と接客に戻す。アプリの主役は「分析」とし、画面の並び順や見出しでも分析を先に大きく扱う。

2. 利用者と毎日の運用

利用者ホテル・旅館の支配人、フロントスタッフ（宿泊の大半は1泊。観光・出張・家族旅行など）
流れ① 現場で受けた声は、その日のうちに記録し対応状況を更新 → ② 毎日夕方、OTA管理画面や口コミ管理サービスから口コミCSVを取り出して読み込む → ③ ボタン1つで口コミと現場の声をまとめて分析 → ④ 現場スタッフへ日次メールを送る
設計思想データを取りに行くのはオーナー。アプリは渡されたCSVを分析するだけ（自動収集はしない）。

3. 機能一覧と進捗（MVP）

#機能内容状態
1口コミCSVの読み込み標準形式と口コミコムの出力CSVを列名から自動で判別（UTF-8／Shift_JIS）。おかしな行は「○行目：理由」を表示。口コミ一覧は年・月・日で絞り込め、返信済み／未返信、外国語の日本語訳も表示。完了
2現場の声の記録受付日・経路・お客様の区分・内容・評価（任意）・対応状況・対応内容を記録。氏名・電話番号・部屋番号の欄は作らず、内容に書かれていれば注意を出す。完了
34軸分析・優先改善アラート・よいコメント・経路別の比較（主役）口コミと現場の声を同じ4軸にAIで分類。期間は年・月・週（月曜始まり）から選び、1つ前の期間と「不満の割合」で比べる。不満が多い・増えた軸をアラートにし、コメントを全文表示。要約は件数・割合をアプリが計算し、AIには不満・好評の内容だけを書かせる。完了
4評価点の集計当日・今月の平均、前月比、前年比。月別平均・月別件数・今月の日別平均のグラフ、サイト別平均の表（AIを使わず計算）。完了
5日次メール当日の口コミ（外国語は和訳付き）と現場の声、今月の要約、評価点を送信。外資系ホテルも想定し、項目名・バッジは英語、文章は日本語。その日の内容を先に、月の要約は最後に短く置く。完了
6分析結果のCSV書き出し4軸の判定を付けて1件1行で書き出す（Excelで文字化けしない形式）。完了
7返信下書き（補助）口コミ1件ごとにボタンで1案を作成し、画面で直してコピーする。口コミと同じ言語で書き、季節感・館内サービスは施設設定にある事実だけを使う。完了

5. システム構成と使う技術

技術（用途）選んだ理由
Next.js 16・TypeScript（画面とサーバー処理）画面とAPI（サーバー側処理）を1つのプロジェクトで作れ、Vercelにそのまま公開できる。型でデータの形の食い違いを防ぐ。
Tailwind CSS／Recharts（見た目・グラフ）スマホ幅・ダークモードへの対応を少ない記述で書ける／Reactの部品としてグラフを書ける。
Papa Parse（CSVの読み込み）本文中のカンマ・改行・引用符を正しく扱える定番ライブラリ。
Claude API（分類・要約・返信下書き）日本語の文脈理解が必要なため。サーバー側からのみ呼び出し、APIキーを画面に出さない。
Resend（日次メール）無料枠（月3,000通）があり、APIで簡単に送れる。

6. データ設計

読み込めるCSV①標準形式（date, site, rating, text, stay_type）　②口コミコムの出力（投稿日時・口コミサイト・★の数・タイトル・コメント・言語・翻訳コメント・返信内容 など）。列名から自動で判別する。
読み込みのルールCSVの最新日を「当日」とする。評価は1.0〜5.0の小数も受け付ける。外国語は日本語訳を分析に使い原文も残す。本文のない「評価のみ」の投稿は評価点の集計にだけ使う。上限は5MB・5,000行。
現場の声受付日・経路・お客様の区分・内容・評価（任意）・対応状況（未対応／対応中／完了）・対応内容。ブラウザ内に自動保存し、CSVで書き出し・読み込み。評価点のグラフには混ぜない。
データの扱いサンプルはすべて架空（口コミ296件・現場の声123件、13か月分）。お客様の氏名・電話番号・部屋番号の欄は作らない。データベースは使わない。

7. 画面設計

タブで 分析ダッシュボード／口コミ一覧／現場の声の記録 を切り替える。分析ダッシュボードは上から「① CSVを読み込む → ② 分析結果（4軸分析・評価点の推移） → ③ 日次メール」の順で、主役の分析を先に置く。返信の下書きは口コミ一覧の各口コミに控えめなボタンで置く。

8. AI設計（費用を抑え、事実と違うことを書かせない）

  • モデルの使い分け：分類・要約は Claude Haiku 4.5（100万トークンあたり入力$1／出力$5）、自然な文章が求められる返信下書きだけ Sonnet 5（$2／$10）。モデル名は環境変数で切り替え、開発中は Haiku 4.5 とダミーの結果で進めた。
  • 分類：25件ずつ送り、決めたJSONの形（Structured Outputs）で4軸の判定を受け取る。分類するのは選んだ期間と1つ前の期間だけで、結果は画面内で使い回し、まだ分類していない分だけを送る。
  • 数字はAIに書かせない：AIに件数まで書かせたところ数え間違いが出たため、件数・割合はアプリが計算し、AIには「不満の内容」「好評の内容」の文だけを書かせる形に改めた。
  • 返信下書き：施設設定（館内サービス・月ごとの季節の話題）にある事実だけを使わせ、改善の約束はさせない。試作で英語の施設名のつづり違いや、ない設備（最上階の客室）を書く誤りが出たため、プロンプトで明示して防いだ。
  • お客様の文章の扱い：口コミ・現場の声の本文はデータとして渡し、中に書かれた指示には従わないようプロンプトで指定する。

9. セキュリティ

  • APIキーは .env.local と Vercel の環境変数だけに置き、.env* はGitHubに上げない。コミット前に毎回確認する。
  • 費用がかかる操作（AIでの分類・要約・返信、メール送信）は、デモ用パスコードとサーバー側の1日の上限（分類2,000件・要約30回・メール10回・返信100回）で守る。メールの送り先はサーバーの設定で固定する。
  • メールに載せる本文はエスケープし、CSV書き出しでは先頭の = + - @ を無害化する（Excelで数式として動かないように）。現場の声に電話番号や「○○様」があれば、保存前に注意を出す。

効果測定結果

11. 主な判断と理由

判断理由
返信ではなく分析を主役にするAIによる返信文作成は大手ツールやGoogleがすでに提供している。差がつくのは、施設に合った軸での分析と改善点の提示。
現場の声も同じ4軸で扱うネットと現場に同じ不満が出ていれば優先度が高いと判断できる。経路で比べると「ネットには出ないが、フロントには多い」不満も見つかる。
期間の比較は件数でなく「不満の割合」期間によって口コミの件数が違うため、件数で比べると「全部の軸が悪化」のような誤った結論になった。
前提を「1泊中心」に修正、口コミコムのCSVに対応実際の利用者に合わせて施設設定とサンプルを作り直した。現場が使う出力をそのまま読めることが毎日使われる条件になる（実在の口コミの中身は使っていない）。
DBを使わず、現場の声はブラウザ内保存＋CSV期限内に確実に作るため。共有はCSVで行い、データベースでの共有は今後の課題にした。

12. 今後の課題

  • 現場の声の共有：複数のスタッフが同じデータを見られるよう、データベースとログインを導入する。
  • 口コミの統合：CSVにできないサイトの口コミの取り込みと、サイトをまたいだ重複の除外。返信の口調・目的の選択。
  • 事業面：支配人への聞き取りで、支払意思額と、口コミや現場の声の分析にかけている時間を確かめる。
